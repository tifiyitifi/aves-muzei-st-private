# Collection paging — rule register

One row per case the feature has to get right. Coverage tokens are defined in
`docs/README.md`; `scripts/check-collection-paging-rules.ps1` resolves every
`F:` token.

## Engine decision

| ID | Case | Behaviour | Why | Coverage |
| --- | --- | --- | --- | --- |
| ENG-1 | Default engine | WHEN no value is stored, THE SYSTEM SHALL use `auto` | large libraries must not crash on a fresh install | `F:collection_paging_prefs_test#defaults to auto` |
| ENG-2 | Member round trip | WHEN an engine name is stored and read, THE SYSTEM SHALL keep the member | a value must survive a restart | `F:collection_paging_prefs_test#tryParse round-trips member names` |
| ENG-3 | Unknown engine | WHEN the stored name is unknown, THE SYSTEM SHALL reject it | a stale name must not select a path by accident | `F:collection_paging_prefs_test#tryParse rejects unknown and null` |
| ENG-4 | Auto pages | WHEN the library is at or above the threshold, THE SYSTEM SHALL page | windowing is the safe default | `F:collection_engine_router_test#auto pages at or above the threshold` |
| ENG-5 | Auto stays legacy | WHEN the library is below the threshold, THE SYSTEM SHALL keep the legacy path | small libraries keep full-grid behaviour | `F:collection_engine_router_test#auto keeps legacy below the threshold` |
| ENG-6 | Explicit legacy | WHEN legacy is selected, THE SYSTEM SHALL use it even above the threshold | the override is the escape hatch | `F:collection_engine_router_test#explicit legacy always wins, even above threshold` |
| ENG-7 | Explicit paged | WHEN paged is selected, THE SYSTEM SHALL page even a small collection | the override must be honoured | `F:collection_engine_router_test#explicit paged forces the path on small collections` |
| ENG-8 | Unsupported filters | WHEN SQL cannot express the scope, THE SYSTEM SHALL keep legacy | a wrong predicate would show the wrong rows | `F:collection_engine_router_test#unsupported filters keep the legacy path` |
| ENG-9 | Hidden filters | WHEN hidden filters exist, THE SYSTEM SHALL compile them into the predicate | hidden rows must not appear in a window | `F:collection_engine_router_test#hidden filters are compiled into the predicate` |
| ENG-10 | Vault | WHEN a vault is locked, THE SYSTEM SHALL page it and keep its rows hidden | the vault is excluded by subtree | `F:collection_engine_router_test#a locked vault still pages, and its rows stay hidden` |
| ENG-11 | Probe failure | WHEN the size probe fails, THE SYSTEM SHALL keep legacy | a guessed small size would materialize the library | `F:collection_engine_router_test#a failed probe keeps the legacy path` |
| ENG-12 | Whole library | WHEN routing answers, THE SYSTEM SHALL answer for the library, not the scope | a small scope in a huge library is still unsafe | `F:collection_engine_router_test#answers for the whole library, not for the scope` |
| ENG-13 | Import running | WHEN the library is being imported, THE SYSTEM SHALL never fully load it | a half-filled database is not the library | `F:collection_engine_router_test#a library still being imported is never fully loaded` |
| ENG-14 | Unprovable size | WHEN the size cannot be proven small, THE SYSTEM SHALL not full-load | memory must not be gambled | `F:collection_engine_router_test#an unprovable size is not a safe full load` |
| ENG-15 | Narrow scope | WHEN a scope is small but the library is large, THE SYSTEM SHALL keep the predicate | the view can be served windowed later | `F:collection_engine_router_test#a below-threshold scope keeps its predicate when the library is too large` |
| ENG-16 | Legacy waits import | WHEN legacy is explicit, THE SYSTEM SHALL still wait for the import before loading | loading mid-import shows a partial library | `F:collection_engine_router_test#an explicit legacy engine still waits for the import to finish` |
| ENG-17 | Small full load | WHEN the library is provably small, THE SYSTEM SHALL allow a full load even under a paged preference | paging a tiny library is unnecessary | `F:collection_engine_router_test#a paged preference does not forbid a provably small full load` |
| ENG-18 | Legacy preference | WHEN legacy is selected above the threshold, THE SYSTEM SHALL honour it | see ENG-6 | `F:collection_engine_router_test#honours an explicit legacy engine above the threshold` |
| ENG-19 | Catalogued face | WHEN a filter is compiled, THE SYSTEM SHALL match the catalogued metadata map | the SQL and in-memory faces must agree | `F:collection_filter_sql_test#match CatalogMetadata.toMap` |

## Preferences

| ID | Case | Behaviour | Why | Coverage |
| --- | --- | --- | --- | --- |
| PRF-1 | Defaults | WHEN nothing is stored, THE SYSTEM SHALL use the documented defaults | a fresh install needs no migration | `F:collection_paging_prefs_test#starts on defaults when nothing is persisted` |
| PRF-2 | Window clamp | WHEN a window size is stored, THE SYSTEM SHALL clamp it into 1..max | a window is a memory budget | `F:collection_paging_prefs_test#clamps window size into 1..max` |
| PRF-3 | Threshold clamp | WHEN a threshold is stored, THE SYSTEM SHALL clamp it into 1..max | an out-of-range threshold disables paging | `F:collection_paging_prefs_test#clamps the large threshold into 1..max` |
| PRF-4 | Round trip | WHEN values are persisted, THE SYSTEM SHALL reload them | the choice outlives a restart | `F:collection_paging_prefs_test#persists and reloads values` |
| PRF-5 | Garbage | WHEN a persisted value is unreadable, THE SYSTEM SHALL fall back to defaults | one bad value must not break loading | `F:collection_paging_prefs_test#falls back to defaults on garbage` |
| PRF-6 | Completion in memory | WHEN the import completes, THE SYSTEM SHALL record it before touching the store | a lost write must not re-import | `F:collection_paging_prefs_test#records completion in memory before touching the preference store` |
| PRF-7 | Notify on change | WHEN a value does not change, THE SYSTEM SHALL not notify | listeners rebuild the view | `F:collection_paging_prefs_test#notifies listeners only on actual change` |

| IMP-14 | Id precedence | WHEN a batch has rows with and without an id, THE SYSTEM SHALL keep the id the store already had | merging must not drop identity | `F:paged_sync_test#keeps the id when the report without one wins the merge`; `F:paged_sync_test#keeps the content id a stored row already had` |
| IMP-15 | Status progress | WHEN progress arrives late, THE SYSTEM SHALL keep the denominator and report the count | the status must not jump backwards | `F:paged_import_status_test#reports progress and keeps the denominator when it lands late` |
| IMP-16 | Status ends once | WHEN the import ends, THE SYSTEM SHALL end the status once and stop notifying | a finished status must not keep rebuilding the app bar | `F:paged_import_status_test#ends once and stops notifying afterwards`; `F:paged_import_status_test#ignores progress a finished run left in flight` |
| IMP-17 | Explainer | WHEN the explainer is shown, THE SYSTEM SHALL raise it once until a surface takes it | the mode removes features and must be explained | `F:paged_import_status_test#raises the explainer once until a surface takes it` |

## Change-based sync

| ID | Case | Behaviour | Why | Coverage |
| --- | --- | --- | --- | --- |
| SYN-1 | Quiet generation | WHEN the generation is unchanged, THE SYSTEM SHALL do nothing | a poll must stay cheap | `F:paged_sync_test#is a no-op when the generation is unchanged` |
| SYN-2 | First baseline | WHEN the generation is unknown, THE SYSTEM SHALL baseline it without backfilling | the import owns the first fill | `F:paged_sync_test#baselines an unknown generation without backfilling` |
| SYN-3 | Changed files | WHEN the generation moves, THE SYSTEM SHALL insert the changed files | that is the whole point of the cursor | `F:paged_sync_test#inserts changed files` |
| SYN-4 | Retry list | WHEN a change fails transiently, THE SYSTEM SHALL keep it and write the list before the cursor | the new cursor would hide the failure | `F:paged_sync_test#retries a change a transient failure left behind instead of losing it`; `F:paged_sync_test#writes the retry list before the cursor that would hide it`; `F:paged_sync_test#keeps the cursor when the retry list cannot be persisted` |
| SYN-5 | Inline catalogue | WHEN a file is synced, THE SYSTEM SHALL catalogue it inline | new rows are the steady-state catalogue | `F:paged_sync_test#catalogs synced files inline` |
| SYN-6 | Obsolete rows | WHEN files vanish, THE SYSTEM SHALL settle the whole change set once | per-row checks cost a platform round trip each | `F:paged_sync_test#removes obsolete files`; `F:paged_sync_test#checks obsolescence once for the whole change set` |
| SYN-7 | No content id | WHEN a changed row has no content id, THE SYSTEM SHALL match it by URI | matching by null would duplicate it | `F:paged_sync_test#updates a changed row without a content id by URI instead of inserting it again`; `F:paged_sync_test#removes an obsolete row that was stored without a content id` |
| SYN-8 | Id lifecycle | WHEN an id is zero, reassigned or withdrawn, THE SYSTEM SHALL keep the row consistent | ids are reused by the platform | `F:paged_sync_test#treats a zero content id as absent`; `F:paged_sync_test#removes a row whose id was handed to another file`; `F:paged_sync_test#keeps the content id a row already had when the provider stops reporting it` |
| SYN-9 | Same file | WHEN the live id still names the same file, THE SYSTEM SHALL keep the row | a reused id is not always a different file | `F:paged_sync_test#keeps a row whose live id still names the same file` |
| SYN-10 | Unknown changes | WHEN a change cannot be resolved, THE SYSTEM SHALL ignore it | a ghost URI must not fail the sync | `F:paged_sync_test#ignores unresolvable changes` |
| SYN-11 | Database-only delete | WHEN entries are removed, THE SYSTEM SHALL delete database rows without materializing | a delete over a paged view cannot load entries | `F:paged_sync_test#removeEntries deletes from the database without materializing`; `F:paged_sync_test#cleanEmptyAlbums keeps directories on an entry-free source` |
| SYN-12 | Sweep guards | WHEN a sweep would drop most of the library or a volume is unmounted, THE SYSTEM SHALL refuse | a disconnected volume looks like mass deletion | `F:paged_discoverer_sweep_test#a sweep that would drop most of the library is refused`; `F:paged_discoverer_sweep_test#an unmounted volume is never asked about` |
| SYN-13 | Sweep by id | WHEN the store no longer serves a row, THE SYSTEM SHALL remove it by row id | a stale id must not delete a live row | `F:paged_discoverer_sweep_test#a row the store no longer serves is removed by its row id`; `F:paged_discoverer_sweep_test#a live library removes nothing` |
| SYN-14 | Event burst | WHEN platform events burst, THE SYSTEM SHALL coalesce one sync and publish once | one publish per event would rebuild the view repeatedly | `F:paged_media_store_bridge_test#a burst of events costs one sync and publishes once`; `F:paged_media_store_bridge_test#a quiet generation publishes nothing`; `F:paged_media_store_bridge_test#a failed sync is swallowed, not published` |
| SYN-15 | Import owns discovery | WHEN an import runs, THE SYSTEM SHALL leave the browser alone | two discovery paths would race | `F:paged_media_store_bridge_test#an import owns discovery while it runs`; `F:paged_media_store_bridge_test#the browser is left alone while the database is filled` |
| SYN-16 | Media op settle | WHEN a media operation is in flight, THE SYSTEM SHALL wait before syncing | a move would be seen as delete + insert | `F:paged_media_store_bridge_test#a change during a media operation waits for it to settle`; `F:paged_media_store_bridge_test#a change arriving mid-run lands in the next pass` |
| SYN-17 | Resume order | WHEN a resume applies changes, THE SYSTEM SHALL refresh summaries before telling the views | the view must not paint against stale counts | `F:paged_resume_sync_test#applied changes refresh the summaries before the views are told`; `F:paged_resume_sync_test#a second resume while one runs is dropped`; `F:paged_resume_sync_test#a quiet generation does nothing`; `F:paged_resume_sync_test#a failed sync is swallowed, not published` |
| SYN-18 | Sweep once | WHEN the process starts, THE SYSTEM SHALL run the obsolete sweep once | a sweep per resume would churn the database | `F:paged_resume_sync_test#the sweep runs once per process`; `F:paged_resume_sync_test#a swept row the store no longer serves refreshes like a change` |
| SYN-19 | Half-filled library | WHEN the database is still being filled, THE SYSTEM SHALL leave browsing alone | the import owns the view's lifecycle | `F:paged_resume_sync_test#browsing a half-filled database is left alone`; `F:paged_resume_sync_test#the in-memory engine refreshes itself` |
